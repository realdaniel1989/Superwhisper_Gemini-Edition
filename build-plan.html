02

How the pieces talk

Browser captures audio → SvelteKit edge route adds your secret key → Groq transcribes → response streams back. Five hops, all measured in milliseconds.

The whole request round-trip for a typical short clip lives in the 800ms–1.2s range — most of which is network, not compute. The edge worker exists for one critical reason: your API key never touches the browser. See §04.

03

Audio capture & the 25MB problem

This is the part that bites people. The browser-side audio pipeline has a dozen footguns, and Whisper's 25MB upload limit will eventually meet a user who records a 90-minute meeting.

DO
Pick the right codec
Record to audio/webm; codecs=opus at 16kHz mono. Opus is ~10× smaller than WAV for the same intelligibility. Whisper downsamples to 16kHz anyway, so capturing higher is wasted bandwidth.
WATCH
Safari hates WebM
Safari's MediaRecorder won't produce WebM. You'll need audio/mp4 as a fallback. Feature-detect with MediaRecorder.isTypeSupported().
RISK
The 25MB ceiling
At 16kHz mono Opus, that's roughly 60–90 minutes of speech. Past that, Groq rejects the request. Plan for chunking: split on silence gaps, transcribe in parallel, stitch results. Or cap recording length in v1.
WATCH
Permission flow is a state
getUserMedia() can be: pending, granted, denied permanently, or denied-then-changed. Your "idle" state needs to handle "no mic permission" distinctly — with a clear path to fix it.
DO
Reuse the AudioContext
Browsers limit how many AudioContexts you can create. Construct one on first interaction, reuse it. Resume from suspended state if needed (autoplay policy).
DO
Voice activity detection
Auto-stop after N seconds of silence — your mockup hints at this. Implement with an AnalyserNode reading RMS, debounced over 200ms windows. ~30 lines of code, huge UX win.
04

The API key & abuse problem

Anyone can open dev tools. If your Groq key ships to the browser, it will be scraped, posted to Discord, and used to transcribe 10,000 hours of someone else's audio on your dime. Within days.

CRITICAL
Never call Groq directly from the browser. Always proxy through your own server route. This is the single most important architectural decision in the build.

The proxy route is small — maybe 40 lines of TypeScript — but it has to do three jobs:

  • Forward the audio to Groq with your secret key from env.GROQ_API_KEY, never hardcoded.
  • Rate limit by IP — Cloudflare's native rate limiting handles this. Start conservative: 10 requests/min per IP, raise if you hit complaints.
  • Validate input — reject non-audio MIME types, cap upload size at the Groq limit, reject empty files. Cheap protection against malformed requests.

If you ever open the app to public use without auth, add Cloudflare Turnstile (their CAPTCHA replacement) on first request from each IP. It's invisible to real users and stops automated scraping cold.

05

Error states & UX edges

The mockup covers four happy states. There are at least eight unhappy ones. Designing them up front is the difference between a demo and a product.

EDGE
Mic permission denied
Show a distinct screen explaining how to re-enable in browser settings. Don't loop the permission prompt — once denied, you can't ask again programmatically.
EDGE
No mic detected
Different from "denied." User has no input device at all. Disable record, explain why.
EDGE
Network failure mid-upload
User finished recording, upload failed. Don't lose their audio. Keep the blob in memory, show "Retry" button.
EDGE
Empty / silent recording
Whisper sometimes returns " " or hallucinates "Thanks for watching!" on silent audio. Detect short/empty transcripts and prompt to retry.
EDGE
Rate limit hit
Your own rate limit or Groq's. Show countdown to retry, don't just say "error."
EDGE
Recording too long
Approaching the 25MB cap. Warn at 80%, hard stop at 95%. Show estimated remaining time in the header strip.
EDGE
Tab backgrounded mid-record
Browsers throttle requestAnimationFrame in background tabs — the waveform stops, but recording continues. Indicate clearly when user returns.
EDGE
Slow transcription
If Groq is congested and the request takes >5s, communicate progress. Long silent spinners feel broken. Show estimated time, or "still working."
06

Performance budget

Set explicit numbers up front. "Fast" without a target is meaningless. These are aggressive but achievable for an app this small.

Metric Target Stretch How to measure
Initial JS payload (gzipped) < 50 KB < 30 KB Vite build report
Time to interactive < 800 ms < 500 ms Lighthouse / WebPageTest
Tap-to-record latency < 150 ms < 80 ms Performance.now() between events
Stop → transcript appears < 1500 ms < 900 ms End-to-end timer in client
Waveform frame rate 60 fps 60 fps Chrome DevTools perf panel
Worker cold start < 50 ms < 10 ms CF Workers analytics

Measure these on real hardware and a throttled "Slow 4G" connection in DevTools, not just on your dev machine. The gap between "feels fast on my M3 Max" and "feels fast on a 3-year-old Android" is where products lose users.

07

Browser & mobile gotchas

SAFARI
MediaRecorder formats
Safari 14+ supports MediaRecorder but with limited codec options. Use feature detection — request audio/mp4 if WebM isn't supported. Both are fine for Whisper.
SAFARI
AudioContext autoplay
Must be created or resumed inside a user gesture (click/tap). Don't construct it on page load — wait for the record button click.
MOBILE
iOS background recording
iOS suspends MediaRecorder when the tab loses focus. There's no fix on Web — only PWAs with audio focus declared can sometimes work around it. Document this limitation.
MOBILE
Keyboard shortcuts
⌘⇧R reloads the page in most desktop browsers. Pick a different shortcut, like ⌘. or a hold-to-record affordance.
DESKTOP
HTTPS required
getUserMedia() only works on HTTPS (or localhost). Cloudflare gives this for free, but local network testing on a phone won't work over plain HTTP.
DESKTOP
Visualizer = battery drain
Continuous requestAnimationFrame + Canvas keeps the CPU warm. Pause the loop when the tab is hidden — listen to visibilitychange.

Build in this order

Get the audio pipeline working end-to-end before touching the design. Nothing kills a project faster than a beautiful UI hooked to nothing.

PH 01 Day 1–2

Walking skeleton

Bare SvelteKit page, one button, MediaRecorder → POST → /api/transcribe → Groq → display text. No styling. No states. Just prove the pipeline works locally.

Audio in, text out, ugly but functional
PH 02 Day 3–4

State machine

Implement idle / recording / transcribing / result / error states with proper transitions. Use a state machine library (XState lite, or just typed unions). Cover the error states from §05.

All 8+ states reachable, no UI polish yet
PH 03 Day 5–7

UI port

Port the mockup HTML/CSS into Svelte components. Component-scoped styles. Wire up the state machine to view switching. This is where the design comes alive.

App matches the mockup, all states styled
PH 04 Day 8–9

Waveform & meters

Hook the Canvas oscilloscope to the real AnalyserNode. Implement the level meter and clarity indicator from live audio data. Tune the smoothing constants.

Real waveform tracks real voice
PH 05 Day 10

Deploy to edge

Cloudflare Pages connected to Git. Configure secrets. Test the full flow from production URL. Add rate limiting. Measure latency from a phone on cellular.

Live URL, key safely stored, rate-limited
PH 06 Day 11–14

Polish & harden

Keyboard shortcuts. Auto-stop on silence. Browser-specific fixes (Safari codec, iOS quirks). Lighthouse pass. Set up Sentry. Write a one-page landing for SEO.

Production-grade. Share with friends.

FYI

10

Pre-launch checklist

  • API key in env, never in code. Verify with a clean clone — the app should refuse to start without the secret set.
  • Rate limiting active in production. Test it: hammer your own endpoint, confirm 429s start coming back.
  • HTTPS everywhere. Cloudflare gives this by default. Verify no mixed-content warnings.
  • Permissions UX tested in 3 browsers. Chrome, Safari, Firefox. Try denying, then re-allowing.
  • Mobile tested on a real device. Not just DevTools emulation. iOS Safari is the harshest reviewer.
  • Slow network tested. Throttle to Slow 4G, verify the upload state and progress feel responsive.
  • Error states all hit at least once. Deny mic, kill wifi mid-upload, record silence, exceed the size cap.
  • Lighthouse score ≥ 95 on Performance, Accessibility, Best Practices.
  • No console errors in any state, on any supported browser.
  • Privacy text written. Audio is sent to Groq for transcription. Not stored. Say so plainly.
  • Source maps disabled in production (or uploaded to Sentry only). Default Vite behavior is fine.
  • Custom domain configured. jediwhispers.app reads better than jediwhispers.pages.dev.
