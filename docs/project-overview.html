01What This Project Is

Jedi Whispers is a dark-themed, single-page browser application for voice dictation. The user presses a record button (or triggers via keyboard shortcut / Chrome extension), speaks into their microphone, and receives an AI-transcribed text result that is automatically copied to the clipboard.

Core experience in four states:

StateWhat the user sees
idle"Speak, and I'll listen." — record dial inviting a tap
recordingLive oscilloscope waveform + Web Speech API preview text
transcribingAnimated progress bar — "Turning sound into words."
resultEditable textarea with transcription, copy & discard buttons
💡

The single most important thing to understand: the backend exists solely to proxy the Groq API key. The API key is never exposed to the client. Audio goes from browser → Express (as base64 JSON) → Groq Whisper → text back to browser.

04Data Flow — Record to Transcription

1. TRIGGER User clicks record button / keyboard shortcut / extension / ?autostart=true │ 2. CAPTURE getUserMedia() → MediaRecorder (webm/opus, 48kHz, echo cancel, noise suppress) │ AudioContext + AnalyserNode for waveform (canvas oscilloscope) │ webkitSpeechRecognition for live preview text │ 3. STOP MediaRecorder.stop() → chunks assembled into Blob │ Stream tracks stopped, AudioContext closed, SpeechRecognition stopped │ 4. SEND src/lib/api.ts: Blob → FileReader → base64 string │ POST to ${VITE_API_URL}/api/transcribe │ JSON body: { audio: "base64...", mimeType: "audio/webm" } │ 5. PROXY server/routes/transcribe.ts: base64 → Buffer │ server/services/groq.ts: Buffer → FormData → Groq API │ Model: whisper-large-v3-turbo │ Bearer token from GROQ_API_KEY env var │ 6. REFINE server/services/refine.ts: raw Whisper text → Groq chat completions │ Model: openai/gpt-oss-20b (temperature 0.3) │ Three-layer refinement: mechanical cleanup, structural formatting, contextual accuracy │ On failure: falls back to raw text, response includes refined: false │ 7. RETURN Express → browser with { text: "...", refined: true/false } │ window.focus() + navigator.clipboard.writeText() (auto-copy) │ Toast notification: "Transcription complete — copied to clipboard" │ If unrefined: "Refinement unavailable — showing raw transcription."
⚠️

Why base64 JSON instead of multipart? The code comment in src/lib/api.ts says it explicitly: "Uses JSON + base64 to avoid corporate proxy issues with multipart uploads." Zscaler or similar corporate proxies can inspect and block multipart form uploads. JSON passes through cleanly.

This is why the Express server has a 50MB JSON body limit — base64-encoded audio is ~33% larger than the original binary.

Derived Display State

const displayState: 'idle' | 'recording' | 'transcribing' | 'result' =
  isRecording ? 'recording'
  : isTranscribing && !transcription ? 'transcribing'
  : transcription ? 'result'
  : 'idle';

This single variable drives the entire UI. Every section of the JSX conditionally renders based on displayState.

BroadcastChannel Communication

The app listens on channel 'superwhisper-recording' and responds to four actions:

ActionBehavior
startStarts recording if not already recording
stopStops recording if currently recording
toggleToggles recording state
statusResponds with current recording state

Also exposes window.superwhisper global object with start(), stop(), toggle(), status() methods.

Toast System

src/components/Toast.tsx provides a context-based toast system:

  • ToastProvider wraps the app at the top level
  • useRegisterGlobalToast() hook (called in AppWithToast) registers the global toast() function
  • toast(message, { type: 'success' | 'error' }) — global function, callable from anywhere
  • Auto-dismiss after 3 seconds

Audio MIME Type Fallback

The recorder tries these MIME types in order, picking the first supported one:

1. 'audio/webm;codecs=opus'   ← preferred
2. 'audio/webm'
3. 'audio/mp4'
4. 'audio/ogg;codecs=opus'
5. ''                          ← let browser decide

Route Map

MethodPathHandlerPurpose

Transcription Pipeline (server-side)

POST /api/transcribe
  ↓
  req.body = { audio: "base64string", mimeType: "audio/webm" }
  ↓
  Buffer.from(audio, 'base64')          // Decode base64 → raw buffer
  ↓
  transcribeAudio(buffer, mimeType)      // server/services/groq.ts
  ↓
  FormData:
    file = new Blob([buffer], {type: mimeType})  named "recording.webm"
    model = "whisper-large-v3-turbo"
    response_format = "json"
  ↓
  fetch("https://api.groq.com/openai/v1/audio/transcriptions", {
    headers: { Authorization: "Bearer ${GROQ_API_KEY}" },
    body: formData
  })
  ↓
  Groq returns { text: "raw transcribed text..." }
  ↓
  refineText(rawText)                    // server/services/refine.ts
  ↓
  Groq chat completions:
    model = "openai/gpt-oss-20b"
    temperature = 0.3
    System prompt: mechanical cleanup + structural formatting + contextual accuracy
  ↓
  Response: { text: "refined text...", refined: true }
           └── On refinement failure: { text: "raw text...", refined: false }

CORS Configuration

server/middleware/cors.ts allows:

  • Origin: FRONTEND_URL env var (defaults to http://localhost:3000)
  • Methods: GET, POST, OPTIONS
  • Headers: Content-Type, Authorization
  • Credentials: enabled
ℹ️

Production doesn't need CORS because Express serves the frontend from the same origin. The CORS config is for local development where Vite runs on port 3000 and Express on port 3001.

Stale Files

server/types.ts exports TranscriptionOptions and TranscriptionChunk interfaces that are not used anywhere in the current codebase. These are leftovers from an earlier streaming implementation.

07Chrome Extension ("Superwhisper Remote")

How It Works

1. User presses global keyboard shortcut from any tab 2. background.js service worker receives chrome.commands.onCommand event 3. Searches for an open tab at localhost:3000 or 127.0.0.1:3000 4. If no tab found → opens http://localhost:3000 in new tab 5. Uses chrome.scripting.executeScript() to inject code into the Superwhisper tab 6. Injected code calls window.superwhisper[action]() (or BroadcastChannel fallback) 7. Main app receives the command and starts/stops recording 8. Extension focuses the Superwhisper tab so user sees the result

Keyboard Shortcuts

ActionMacWindows / Linux
Toggle recordingCmd+Option+RCtrl+Shift+R
Start recordingCmd+Option+SCtrl+Shift+S
Stop recordingCmd+Option+XCtrl+Shift+X
⚠️

Cmd+Shift+R is reserved by macOS (AirDrop). That's why the Mac shortcut uses Cmd+Option+R instead. Don't change this.

⚠️

The extension only works with localhost. It searches for tabs at localhost:3000 and 127.0.0.1:3000. It does NOT support the production Railway URL. If you deploy to production, the extension won't work unless updated.

Build Pipeline

Production Architecture

In production (Railway), a single Express process serves both the frontend static files and the API. There is no separate frontend server. VITE_API_URL is empty, so the frontend makes same-origin requests to /api/transcribe.

Oscilloscope Waveform

During recording, a canvas renders a scrolling time-domain waveform with three visual layers:

  1. Glow trail — 2.5px stroke, rgba(198, 247, 78, 0.10)
  2. Main trace — 1.2px stroke, #c6f74e
  3. Leading dot — 2px circle at the rightmost point, with shadowBlur: 6 glow

The waveform scrolls left at SPEED = 1.0 pixels per frame. A 7-bar RMS level meter sits alongside — bars 5+ turn red (the "hot" zone).

Favicon

public/favicon.svg is a lightsaber-themed icon: dark circle with a cyan blade and hilt. Custom SVG, not from an icon library.

11Gotchas, Quirks & Known Issues

🚨

403 Forbidden on production — The Railway deployment has been returning 403 errors on /api/transcribe. This is likely caused by Zscaler corporate proxy intercepting the request to Groq's API. The Zscaler_Diagnostic_Report.docx in the project root confirms proxy issues. The base64 JSON approach was meant to work around this, but the server-to-Groq call can still be blocked.

⚠️

webkitSpeechRecognition is Chrome-only. Firefox doesn't support it. Safari has limited support. The live preview feature only works in Chromium-based browsers. The code doesn't fail gracefully — it just silently skips the live preview.

⚠️

No recording size limit. Groq has a 25MB upload limit, but the app doesn't enforce any cap. Very long recordings could exceed this and fail silently.

More Quirks

IssueDetails
Audio lost on error If transcription fails, the audio blob is discarded. User must re-record. No retry mechanism.
any types recognitionRef is typed as any. window.superwhisper is set via (window as any). No type safety for browser-specific APIs.
No test coverage Zero test files. No test framework configured. No test scripts in package.json.
Unused dependencies multer (was for multipart uploads, replaced by JSON), motion (Framer Motion, imported but not used in components), lucide-react (only used for toast close icon).
Stale server types server/types.ts exports TranscriptionOptions and TranscriptionChunk — used by nothing. Leftover from streaming implementation.
package.json name The name field is "react-example" and version is "0.0.0". The real app identity is in the UI footer: "v 0.5.0".
HMR comment in vite.config.ts There's a comment saying "Do not modify" about HMR disabling. This is for AI Studio agent editing — if you're not using AI Studio, you can ignore it.
build-plan.html is aspirational The build plan describes a SvelteKit + Cloudflare Workers architecture that was never built. The actual stack is React + Express + Railway. Don't treat it as current documentation.

13Project History — What Was Removed

The project went through 4 planned phases. Here's what happened:

PhaseWhat was builtCurrent status
Phase 1: Backend API Express server, Groq proxy (originally OpenRouter), health endpoint active — core of current backend
Phase 2: Authentication Supabase Auth: AuthContext.tsx, AuthModal.tsx, supabase.ts removed — files deleted during UI overhaul
Phase 3: Database Storage Supabase DB: dictations.ts, supabase/migrations/ removed — files deleted during UI overhaul
Phase 4: Deployment Railway config, SPA fallback, static file serving active — railway.json, Express static serving

After Phase 4, a major UI overhaul replaced the light-themed Tailwind UI with the current dark theme + oscilloscope waveform (documented in docs/superpowers/specs/2026-05-11-dark-mode-waveform-design.md). During this overhaul, the Supabase auth and database code was removed, leaving the current streamlined single-user dictation tool.
