🪄 Jedi Whispers — iOS Shortcut Guide

Dictate from any app → AI transcription → paste back

0 What You're Trying to Do

You're in Messages / Notes / any app typing a message ↓ double-tap the back of your phone Jedi Whispers webapp opens → you speak → AI formats it ↓ auto-copies to clipboard Switch back → Paste → done

You're using the Jedi Whispers webapp saved to your iOS home screen. You want to trigger it from any app, dictate, and paste the result back. This guide covers the exact setup and — critically — how to fix the two annoying permission prompts that kill the flow.

1 The Two Problems You're Hitting

Problem 1: "Ready to Record?" prompt every time

Every time the shortcut opens the webapp, you see a modal asking "Ready to Record — Click below to start recording." You have to tap Start Recording before anything happens.

Why: iOS Safari requires a user gesture (tap/click) before any website can access the microphone. This is a hard browser security rule — there is no way for a webpage to start recording automatically without a tap. The autostart modal exists because of this requirement.

The fix: Skip the autostart parameter entirely. Just open the page and tap the big microphone button directly. Same number of taps, but it feels more natural and avoids the modal entirely. See Section 3.

Problem 2: Microphone permission prompt every time

Even though you've granted microphone access before, iOS Safari asks for permission again every time the page loads.

Why: This is a well-known WebKit bug (Bug 215884, Bug 228317). Safari does not reliably persist getUserMedia (microphone) permissions when a page reloads. Each time the shortcut runs "Open URL," it reloads the page in a new context and the permission is lost.

The fixes: See below — there are two things to change.

2 Fixing the Permission Issue CRITICAL

You need to do two things. Both are required.

Fix 1: Grant permanent mic permission in iOS Settings

This tells iOS to remember the permission for this website instead of asking every time.

  1. Open Settings on your iPhone
  2. Scroll down and tap Safari
  3. Tap Microphone (you may need to scroll to the "Privacy" section)
  4. You'll see a list of websites. Find jediwhisper.railway.app
  5. Change it from "Ask" to "Allow"

Can't find the site in the list? Open Safari → visit jediwhisper.railway.app → grant mic permission when prompted → then go back to Settings → Safari → Microphone → the site will now appear. Set it to Allow.

iOS 18 path: Settings → Apps → Safari → Microphone → [find site] → Allow
iOS 17 path: Settings → Safari → Microphone → [find site] → Allow
If you don't see a Microphone section: Visit the site in Safari first, grant permission once, then the section will appear.

Fix 2: Use Safari's "Open URLs" action (not generic "Open URL")

The Safari category "Open URLs" action is smarter — if the URL is already open in a tab, it reuses that tab instead of opening a new one. This means the permission from your previous session is preserved.

  1. Open the Shortcuts app
  2. Find your existing "Jedi Dictate" shortcut (or create a new one with +)
  3. Delete the existing "Open URL" action
  4. Tap Add Action
  5. Search for "Open URLs" — make sure you pick the one under the Safari category (it has a Safari icon), NOT the generic "Open URL" under Web
  6. In the URL field, enter: https://jediwhisper.railway.app
    Note: no ?autostart=true — we're skipping the autostart to avoid the modal
  7. Tap Done

Why this matters: The generic "Open URL" action opens a new tab every time, which loses the permission. The Safari "Open URLs" action reuses the existing tab if it's already open, keeping your permission intact. If no tab is open yet, it opens a new one (and you'll need to grant permission that first time only).

First-time permission grant (do this once)

After making the changes above, you need to grant permission once the "right way":

  1. Open Safari (not the home screen icon — actual Safari)
  2. Navigate to jediwhisper.railway.app
  3. Tap the microphone button on the page
  4. Safari will prompt for microphone access → tap "Allow"
  5. You should see the recording indicator — tap Stop to verify it works
  6. Don't close this tab. Leave Safari open with this tab.
  7. Now go to Settings → Safari → Microphone and confirm the site is set to "Allow"

After this, every time your shortcut runs, it will reuse the existing Safari tab where permission is already granted. No more re-prompting.

3 The Complete Setup

Step A: Create the Shortcut

  1. Open the Shortcuts app → tap +
  2. Tap Add Action
  3. Search "Open URLs" — pick the one with the Safari icon
  4. URL: https://jediwhisper.railway.app (no autostart parameter)
  5. Tap Done → name it "Jedi Dictate"

Step B: Assign a Trigger

Pick one to launch from anywhere:

  1. Back Tap — Settings → Accessibility → Touch → Back Tap → Double Tap → "Jedi Dictate"
  2. Action Button (iPhone 15 Pro+) — Settings → Action Button → Shortcut → "Jedi Dictate"
  3. Control Center (iOS 18+) — Add a Shortcuts control → "Jedi Dictate"
  4. Home Screen widget — Add Shortcuts widget → pick "Jedi Dictate"
  5. Siri — Say "Hey Siri, Jedi Dictate"

Step C: Grant Permissions (one-time — see Section 2)

Follow the steps in Section 2 above. Open the site in Safari, grant mic permission, leave the tab open, and set it to "Allow" in Settings.

Step D: The Day-to-Day Workflow

  1. You're typing in any app (Messages, WhatsApp, Slack, etc.)
  2. Double-tap the back of your phone (or use your trigger)
  3. Safari opens to Jedi Whispers (reuses existing tab — no permission prompt)
  4. Tap the big mic button (one tap — your user gesture)
  5. Speak naturally — AI formats your transcription
  6. Tap Stop (the red square). Text is auto-copied to clipboard
  7. Swipe up from the bottom to go home → reopen your original app
  8. Long-press → Paste — your dictation is inserted at the cursor

⏱️ Total hands-on time: ~5 seconds. Tap mic → speak → tap stop → switch back → paste. The speaking part is hands-free.

4 Troubleshooting

It's STILL asking for microphone permission every time

This means the permission isn't persisting. Try these in order:

  1. Confirm Settings → Safari → Microphone → jediwhisper.railway.app is set to "Allow" (not "Ask")
  2. Make sure your shortcut uses Safari "Open URLs" (with the Safari icon), not generic "Open URL"
  3. Open Safari manually, visit the site, grant permission, and leave the tab open — don't close it
  4. Try removing the home screen bookmark entirely and just use the shortcut to open Safari directly
  5. If nothing works, add ?autostart=true back to the URL — the autostart prompt (tap to start) is unavoidable but at least it combines the user gesture + permission grant into one tap
The Safari "Open URLs" action isn't showing up in Shortcuts

Make sure you're searching for "Open URLs" (plural) or just "URLs". The action should appear under the Safari category with a Safari icon. On older iOS versions it may be called "Open URL in Safari". If you can't find it, the generic "Open URL" still works — you'll just get a new tab each time.

The autostart modal is annoying — can I skip it?

Yes. That's exactly what the setup in Section 3 does — don't use ?autostart=true in the URL. Instead, just tap the big microphone button on the page. It's the same number of taps (one) but feels more natural and avoids the modal dialog.

Why can't the page just auto-record without any tap?

iOS Safari blocks microphone access without a user gesture (a tap or click). This is a hard security rule enforced by WebKit. No website can bypass this. The tap on the mic button IS that user gesture.

I closed the Safari tab and now it's asking for permission again

This is expected — closing the tab (or Safari purging it from memory) resets the permission context. The fix: don't manually close the Jedi Whispers tab. Safari manages tabs automatically and won't close it unless you do. If you have many tabs open and Safari evicts it, just re-grant permission and set it to "Allow" in Settings again.

What if I'm using the home screen bookmark, not Safari?

If you added the site to your home screen via "Add to Home Screen", tapping that icon opens a separate Safari-like window (a WKWebView). Permissions in this context do not persist reliably (WebKit bug). For the smoothest experience, remove the home screen bookmark and use the shortcut to open the site in regular Safari instead. The shortcut already gives you one-tap access, so the bookmark is redundant.

Can I make it auto-paste without switching apps?

Not with a webapp. iOS does not allow websites or Shortcuts to inject text into other apps. You must manually switch back and paste. This is an Apple security restriction. Only native iOS apps with a keyboard extension (like the Superwhisper App Store app) can auto-paste at the cursor.

Does this work offline?

No. Your Railway-hosted webapp needs internet for AI transcription. If you need offline dictation, use the built-in iOS Dictate Text shortcut action (no AI formatting though).

Why does it open a new tab each time instead of reusing the old one?

You're probably using the generic "Open URL" action instead of the Safari-specific "Open URLs" action. See Section 3 for the correct shortcut setup. The Safari version reuses existing tabs.

5 Pro Tips

🚀 Speed up the "switch back"

On iPhones with Face ID, swipe up from the bottom edge to go home, then tap your previous app. Or use the app switcher (swipe up and hold) to jump directly back. On iOS 18+, you can swipe left/right on the bottom bar to quickly switch between your two most recent apps.

⌨️ Quick Paste

After switching back to your app, instead of long-pressing and waiting for the menu, just tap with three fingers on the keyboard area to paste (three-finger pinch-out gesture, iOS 13+). Or tap the cursor and select "Paste" from the popup — it's faster than long-pressing empty space.

📌 Don't use the Home Screen bookmark

The home screen icon opens a WKWebView that doesn't persist mic permissions. Use the shortcut + Safari tab approach instead. The shortcut gives you one-tap access from anywhere, which is what the bookmark was doing anyway.

🎙️ Keep a dedicated Safari tab

Don't close the Jedi Whispers tab in Safari. As long as it stays open, the shortcut will reuse it and permission is preserved. If Safari eventually evicts the tab (you have tons of tabs open), just re-open it and you'll only need to grant permission once more.

6 The "Last Resort" Setup IF PERMISSIONS WON'T STICK

If you've done everything above and iOS still re-prompts for mic permission (this happens on some iOS versions), use this fallback approach with ?autostart=true. It combines the user gesture and permission grant into one tap:

  1. Shortcut: Safari "Open URLs" → https://jediwhisper.railway.app/?autostart=true
  2. When it opens, you'll see the "Ready to Record" modal
  3. Tap "Start Recording" — this serves as both your user gesture AND the permission grant
  4. If iOS prompts for mic permission, tap "Allow" — recording starts immediately
  5. Speak → tap Stop → switch back → paste

Why this works: The autostart modal is annoying but it's actually doing something useful — the tap on "Start Recording" satisfies iOS's user gesture requirement. If you remove autostart and use the mic button, you're doing the same thing. The difference is that the mic button feels less like an interruption.

7 Summary

The recipe:

  1. Settings → Safari → Microphone → jediwhisper.railway.app → Allow (one-time)
  2. Open the site in Safari once, grant permission, leave the tab open
  3. Create shortcut: Safari "Open URLs" → jediwhisper.railway.app
  4. Assign to Back Tap (Settings → Accessibility → Touch → Back Tap)
  5. Day-to-day: double-tap back → tap mic → speak → tap stop → switch back → paste

After initial setup, the flow is: trigger → tap → speak → stop → paste. Five quick interactions. No repeated permission prompts.
